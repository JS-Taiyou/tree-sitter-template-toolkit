# Plan: Fix remaining test failures in `multiple-statements.tt2`

## Problem

Two distinct issues cause all 12 ERROR nodes in `multiple-statements.tt2`:

1. **Inline block constructs** — Lines 5 and 8 use `IF ... END` and `FOREACH ... END` within a single `[% ... %]` directive, separated by `;`. The grammar only supports these as block-level constructs with separate `[% IF %]` ... `[% END %]` tags.

2. **Arithmetic operators** — Line 8 uses `total + item.price` but the grammar has no arithmetic operators (`+`, `-`, `*`, `/`, `%`).

## Grammar Changes

### Change 1: Add `inline_conditional` rule

Add a new rule that matches `IF/UNLESS expr ; body ; ELSIF expr ; body ; ELSE ; body ; END` within a single directive's `_statement_list`.

```javascript
inline_conditional: $ => seq(
  choice('IF', 'UNLESS'),
  $._value_expression,
  repeat(seq(';', $._directive_statement)),
  repeat($.inline_elsif_clause),
  optional($.inline_else_clause),
  ';', 'END'
),
inline_elsif_clause: $ => seq(
  ';', 'ELSIF', $._value_expression,
  repeat(seq(';', $._directive_statement))
),
inline_else_clause: $ => seq(
  ';', 'ELSE',
  repeat(seq(';', $._directive_statement))
),
```

**Key mechanism**: `END`, `ELSIF`, `ELSE` are string literals expected by the enclosing `inline_conditional`. Tree-sitter's lexer produces these string literal tokens instead of `identifier`, causing the body `repeat(seq(';', _directive_statement))` to stop at these keywords.

**Nested inline blocks**: Supported naturally — `_directive_statement` includes `inline_conditional` and `inline_foreach`, so `IF a; IF b; x; END; END` parses correctly.

### Change 2: Add `inline_foreach` rule

```javascript
inline_foreach: $ => seq(
  'FOREACH',
  field('iterator', $.variable),
  field('operator', choice('=', 'IN')),
  field('list', $._value_expression),
  repeat(seq(';', $._directive_statement)),
  ';', 'END'
),
```

### Change 3: Update `_directive_statement`

Add `inline_conditional` and `inline_foreach` to the choice:

```javascript
_directive_statement: $ => choice(
  $.command_expression,
  $.assignment_expression,
  $.comment,
  $.inline_conditional,
  $.inline_foreach,
  $._value_expression
),
```

### Change 4: Add arithmetic operators to `binary_expression`

Add two new precedence levels (4=additive, 5=multiplicative) above the existing concatenation operator (prec 3):

```javascript
binary_expression: $ => choice(
  prec.left(5, seq(field('left', $._value_expression), field('operator', $.multiplicative_op), field('right', $._value_expression))),
  prec.left(4, seq(field('left', $._value_expression), field('operator', $.additive_op), field('right', $._value_expression))),
  prec.left(3, seq(field('left', $._value_expression), field('operator', '_'), field('right', $._value_expression))),
  prec.left(2, seq(field('left', $._value_expression), field('operator', $.logical_op_high), field('right', $._value_expression))),
  prec.left(1, seq(field('left', $._value_expression), field('operator', $.logical_op_low), field('right', $._value_expression))),
  prec.left(0, seq(field('left', $._value_expression), field('operator', $.comparison_operator), field('right', $._value_expression)))
),
multiplicative_op: $ => choice('*', '/', '%'),
additive_op: $ => choice('+', '-'),
```
