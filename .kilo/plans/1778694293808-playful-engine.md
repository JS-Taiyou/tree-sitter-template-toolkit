## Phase 2: Grammar Fixes (`grammar.js`)

### Fix 1: Comment regex eats `%]` closing tag
**Problem**: `extras: [/\s/, $.comment]` with `comment: /#.*/` causes `[%# comment %]` to consume `%]` (regex eats to end-of-line).
**Fix**:
- Remove `$.comment` from `extras` (keep only `/\s/`)
- Add `$.comment` to `_directive_statement` choices
- Change comment regex to `/#[^%]*/` — stops before `%`

### Fix 2: `bare_string` conflicts with `variable`
**Problem**: `bare_string: /[a-zA-Z0-9_.\/]+/` in `primary_expression` greedily matches `user.name.upper` as one token instead of structured `variable(identifier, '.', identifier, '.', identifier)`.
**Fix**:
- Remove `bare_string` from `primary_expression`
- Add `path: /[a-zA-Z0-9_.\/]+/` rule for file paths (INCLUDE/INSERT/PROCESS)
- Use `path` only in `command_expression`
- Add `number: /\d+(\.\d+)?/` to `primary_expression` (was previously matched by bare_string)
- Change `identifier` regex to `/[a-zA-Z_][a-zA-Z0-9_]*/` (no leading digits)

### Fix 3: `SET var = value` — `=` not recognized in command context
**Problem**: `command_expression: keyword + repeat1(value_expression)` can't parse `SET var = value` because `=` isn't valid in `value_expression`.
**Fix**:
- Add `named_argument: seq($.identifier, '=', $._value_expression)`
- Update `command_expression` to: `seq($.keyword, repeat1(choice($.named_argument, $.path, $._value_expression)))`

### Fix 4: Uppercase `AND`/`OR` not recognized
**Problem**: `logical_op_high` only has `'and'` (lowercase), `logical_op_low` only has `'or'` (lowercase).
**Fix**:
- `logical_op_high: choice('&&', 'AND', 'and')`
- `logical_op_low: choice('||', 'OR', 'or')`

### Fix 5: `FILTER` block directive not supported
**Problem**: No grammar rule for `[% FILTER html %]...[% END %]` block form.
**Fix**:
- Add `filter_block: seq($.filter_start_directive, repeat($._statement), $.end_directive)`
- Add `filter_start_directive: seq('[%', 'FILTER', $._value_expression, '%]')`
- Add to `directive` choice
- Add `'FILTER'` to keywords (for inline use)

### Fix 6: `ELSE`/`ELSIF` body content not parsed correctly
**Problem**: `else_directive` puts body content inside the directive node, but body should be at `conditional_block` level (raw HTML is only valid at `_statement` level, not inside `_statement_list`).
**Fix**:
- Restructure `conditional_block` to use `elsif_clause` and `else_clause` wrappers that include body content:
  ```
  conditional_block: seq(
    conditional_start_directive,
    repeat(_statement),           // IF body
    repeat(elsif_clause),         // ELSIF + body
    optional(else_clause),        // ELSE + body
    end_directive
  )
  elsif_clause: seq(elsif_directive, repeat(_statement))
  else_clause: seq(else_directive_marker, repeat(_statement))
  ```
- `else_directive_marker: seq('[%', 'ELSE', '%]')` — just the marker, no body inside
- `elsif_directive` stays the same — just the marker

### Fix 7: Pipe filter with arguments `| truncate(50)`
**Problem**: `filter_expression: expr '|' identifier` can't handle `expr | func(args)`.
**Fix**:
- Update filter_expression to: `prec.left(1, seq(expr, '|', choice($.identifier, seq($.identifier, $.argument_list))))`

## Known Limitations (Not Fixed)
1. **Method calls on literals**: `'hello'.ucfirst()` — needs `value_expression '.' identifier` rule
2. **Inline block constructs**: `[% IF cond; ...; END %]` in single directive — needs separate grammar path
3. **Inline FOREACH**: `[% FOREACH item IN list; ...; END %]` in single directive — same as above
